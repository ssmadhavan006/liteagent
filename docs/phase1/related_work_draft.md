# Related Work

## 1. Complexity-Aware Routing & LLM Cascades
The dynamic selection and routing of queries among a tiered pool of Large Language Models (LLMs) has emerged as a primary strategy to manage inference costs and compute latency. Rather than relying on a single monolithic model for all tasks, systems can route simpler queries to smaller, highly efficient models while reserving complex, high-reasoning tasks for frontier models. RouteLLM (Ong et al., 2024) formalizes this routing choice by training specialized classifiers on human preference data to predict when a smaller model's output will satisfy quality expectations. Similarly, FrugalGPT (Chen et al., 2023) introduces sequential model cascades, escalating queries from cheaper models to larger models based on confidence threshold criteria. Probabilistic programming models for LLM chains (Dohan et al., 2022) provide a formal mathematical foundation for modeling cascades and verification loops. Within model architectures, adaptive self-speculative frameworks (Guo et al., 2024; Google Research, 2024) utilize hierarchical or dynamic cascades of draft models to accelerate generation speed. However, these cascading approaches are designed as single-query pipelines in homogeneous cloud systems, overlooking the system-level memory implications of multi-agent state persistence.

## 2. KV-Cache Management & Memory Systems
Key-Value (KV) cache storage represents the chief memory bottleneck in high-throughput LLM serving. PagedAttention, implemented in vLLM (Kwon et al., 2023), mitigates this by partitioning the KV cache into non-contiguous physical pages to prevent fragmentation, allowing a significant boost in concurrent request handling. To manage context length scaling, StreamingLLM (Xiao et al., 2024) identifies the presence of "attention sinks"—initial tokens that capture disproportionate attention weight—and retains these sinks alongside a sliding context window to enable infinite streaming without retraining. Similarly, H2O (Zhang et al., 2023) compresses KV caches dynamically by evicting tokens with low attention weight, preserving only "heavy hitter" tokens. To scale context sizes beyond VRAM boundaries, systems like InfiniGen (OSDI, 2024) and FlexGen (Sheng et al., 2023) introduce dynamic KV offloading between GPU memory and host memory, predicting active context blocks to overlap PCI transfers with execution. While LMCache (2025) abstracts this offloading into an engine-agnostic tiered layer, existing KV-cache offloading and compression frameworks assume single-agent queries in high-bandwidth datacenter clusters, lacking cross-device optimizations for edge configurations.

## 3. Edge LLM Deployment
Deploying LLMs locally on consumer and edge devices is highly constrained by limited RAM and memory bandwidth. The development of llama.cpp (Gerganov, 2023) democratized local inference by optimizing raw C/C++ execution on ARM CPUs using SIMD vector instructions and GGUF quantization formats. MLC-LLM (MLC Team, 2023) extends edge acceleration by compiling custom execution kernels for diverse mobile and GPU backends. Profiling frameworks such as LLM-Viewer (2024) have verified that memory bandwidth, rather than raw computation, remains the primary bottleneck for edge inference. Consequently, specialized systems like EdgeMoE (2023) optimize Mixture-of-Experts inference by dynamically scheduling parameter loads across memory boundaries. MobileLLM (Li et al., 2024) demonstrates that compact, sub-billion parameter models can achieve high reasoning capabilities when structured with deeper, narrower layers. Despite these optimizations, running larger models (e.g. 7B+) on local edge devices remains bottlenecked by high latency and low token throughput, prompting the need for collaborative offloading to more powerful local workstations.

## 4. Multi-Agent LLM Systems
Multi-agent systems orchestrate collaborative teams of specialized agents to solve complex reasoning, retrieval, and programming tasks. Frameworks like AutoGen (Wu et al., 2024) model collaboration as conversational multi-agent dialogue loops, while MetaGPT (Hong et al., 2024) structures coordination through standardized operating procedures (SOPs) based on engineering roles. CAMEL (Li et al., 2023) pioneers role-playing agent dynamics. To improve consensus and output quality, Mixture-of-Agents (Wang et al., 2024) employs layered agent clusters where multiple smaller models propose draft responses that are consolidated in subsequent layers. However, the collaborative conversational loops in these multi-agent frameworks yield massive, repetitive prefill computations and prompt contexts. KVFlow (2024) attempts to optimize multi-agent cache reuse by scheduling blocks based on static workflow graphs. Yet, none of these multi-agent systems address the latency and memory challenges of deploying agent teams in heterogeneous, low-power edge environments.

## 5. LiteAgent Co-Design Positioning
LiteAgent bridges the gap between edge multi-agent execution and systems-level resource optimization. Existing multi-agent frameworks (e.g. AutoGen, MetaGPT) treat LLMs as black-box APIs, ignoring the severe memory constraints of edge hardware. Conversely, modern KV-cache systems (e.g. vLLM, LMCache) are optimized for single-session cloud serving and fail under the dynamic context switching of multi-agent conversational chains. Our literature review did not identify prior work that combines these capabilities in the same edge-oriented multi-agent setting. LiteAgent addresses this gap through a unified co-design: it schedules and routes sub-tasks dynamically between local edge nodes (Raspberry Pi 5) and workstations based on reasoning complexity, and pairs this with a three-tier persistent KV cache manager (VRAM, local RAM, and SSD/cold storage). By coordinating routing logic and tiered cache placement, LiteAgent prevents memory thrashing, eliminates redundant prefill overhead, and enables high-accuracy multi-agent reasoning on resource-constrained edge hardware.
